# 拾光匣：本地家庭相册与局域网备份设计

本文保留历次设计与验收阶段背景；当前产品原名为「近传 · Jinchuan」，品牌与旧安装兼容规则见 [品牌说明](branding.md)，当前功能概览见 [项目首页](../README.md)。历史跨设备宝宝相册同步段落不代表现有手机功能。

## Android 整理前的完整内容指纹提速（2026-10-05）

宝宝整理、上传准备与备份核对共用原文件身份读取。Android 通过现有媒体通道将完整 SHA-256 交给原生工作线程，复用 256 KiB 读块，避免每张照片启动 Dart isolate 并执行 Dart 哈希。读取前后核对原文件大小与修改时间，同时校验实际读取字节数；读取失败或期间变化明确返回错误，不能使用局部内容或旧身份冒充成功。超过 2 GiB 的媒体在读取前拒绝。

内容 ID、现有缓存与上传回执格式不变。暂停接续、失败重试、人工归属、识别人脸的模型与阈值、视频抽帧和完整分辨率原图预览沿用既有规则。其它平台和本机 Flutter 测试保留独立 isolate 的完整 Dart 哈希；不增加数据库结构、业务依赖或媒体写入能力。指纹步骤的合成文件测量不能代表手机上整库人脸整理的实际提速。

## Android 宝宝整理跨页面运行与断点接续（2026-10-05）

宝宝整理归应用级控制器持有，切换相册、宝宝、传输或普通子页面不暂停、不重建任务。暂停状态直接显示已完成数量。应用真正进入后台、实际传输原文件或主动选择参考时，完成正在处理的当前项后保留断点；回到前台并结束传输时自动接续此前运行的任务，手工暂停不因生命周期或传输通知自动重启。短暂失去焦点不触发后台暂停，未增加 Android 后台服务或锁屏执行承诺。

继续整理不清零已有计数。先分页核对当前授权媒体，再验证完成缓存的系统版本、原文件路径、大小和修改时间；完整分析复用现有结果，失败项保留明确原因，只显式重试。新增、版本变化、文件状态变化或尚未完成分析的媒体进入剩余队列，指纹变化仍建立新的内容身份，原人工归属和历史记录保留。权限收窄或枚举期间范围变化不能沿用旧总数冒充当前完成；范围确认完整且任务完成后才收起失去授权的卡片。

在现有偏好表保存总数、已处理数、复用数、新增分析数、未完成状态及失败重试剩余 ID，不新增数据库表。分析结果先落盘，检查点随后保存；旧版本没有检查点时，从已有当前模型的分析记录恢复初始计数。完成数在当前项处理结束后递增，暂停立即继续等待旧任务保存，避免两个扫描或重试同时分析。失败重试的范围独立保存，继续失败重试不会扩成整库分析。保存失败明确提示；关闭时先结束当前项与检查点写入，再关闭存储。

## Android 宝宝预览移除常驻底栏（2026-10-05）

宝宝相册点开照片后，原文件按比例完整适应整个画布，顶部仅保留返回、收藏与更多。是宝宝、不是宝宝、确认并设为参考、水印显示、照片信息与上传原文件集中到更多菜单，菜单文字随系统字体换行，保留至少 48 像素触控高度；滑动后操作始终作用于当前照片，上传仍返回既有传输流程。水印副本继续从照片信息制作，全局显示偏好、人工归属与参考保存沿用原实现。

日常照片预览不创建底部按钮、遮罩或安全区域占位，点图还可隐藏顶部工具。视频保留播放与进度，主动进入选脸后才显示人脸选项、退出与保存；忙碌、失败或结果提示仅在需要时显示。普通相册保留现有单排操作及备份信息图标。两种预览共用可选底栏布局，不裁切完整画面、不改变原图解码分辨率或新增缩略图预览替代。

## Android 全屏原图预览与单排操作（2026-10-05）

普通相册与宝宝预览共用全屏画布，顶部标题、返回和常用图标浮在原图上，底部工具采用渐变遮罩并保留系统安全区域。点图收起上下工具，再点恢复；忙碌或主动选脸时保留必要操作。画布延伸到顶部与左右，原文件按比例完整显示，小尺寸照片也适应当前显示区域，不以裁切、拉伸、压缩副本或降低解码分辨率消除比例产生的留白。

移除底部上一张、下一张及单独页数行，页数并入顶部说明。普通相册底部将备份信息图标、宝宝整理与传到电脑合成一排；宝宝预览保留是宝宝、不是宝宝，将设为参考和上传改为有明确提示的图标，并按标签长度分配文字按钮空间。水印显示使用原设置，副本制作放在照片信息中；归属、待核对原因、分析失败及拍摄日期继续在信息面板查看。视频播放与进度保留，主动选脸继续提供人脸选项、重试及确认，不挤入日常预览。

左右滑动直接带动当前完整画面，松手后完成约 300 毫秒的滑出、滑入过渡；短滑、竖向操作及首尾边界回弹，不触发归属或传输。放大、双指操作、忙碌和选脸时不切图。系统要求减少动画时直接切换。读图等待不阻止继续浏览，迟到原文件或视频初始化不能覆盖当前页；到已加载末尾沿用原分页获取，不新增原图预解码缓存或业务依赖。

## 桌面原文件元数据修订自动恢复（2026-10-05）

补写拍摄日期或修改文件时间不能直接判定原文件丢失。打开媒体发现大小、修改时间或可用状态变化时，局部核对完整字节；指纹相同只刷新位置状态，指纹变化则建立当前内容索引并刷新图库。重扫同时检查同一授权位置的历史记录，恢复早期版本遗留的失效卡片。

原文件去重、手机备份结论及保存回执继续以完整 SHA-256 和大小为准。额外内容签名仅证明同一位置的元数据修订：JPEG、PNG、WEBP 比较全部非 EXIF 编码数据、方向与颜色属性；HEIF 比较图像项目、布局关系与渲染属性；QuickTime 比较完整媒体数据、编码描述、轨道矩阵与样本表，仅忽略创建和修改时间。解析失败、方向改变或实际图像替换都不自动迁移旧关联，不能用缩略图或相似图片作为证明。

新索引保存内容签名供后续复用；旧索引没有签名时，原始副本及元数据备份必须仍位于授权目录，且完整指纹、大小与旧记录一致后才能取证。不存在可靠原件时保留历史并提示「原文件已变化」，不猜测拍摄日或参考身份。WEBP 的真实 EXIF 段支持 TIFF 与带 EXIF 前缀的形式，文件后缀不影响日期读取。

确认内容未变后保留收藏、人工日期、宝宝加入或排除、原人脸标识和人物命名，并迁移宝宝参考与头像位置；当前新记录的人工决定优先于旧自动结果。新记录已重新人工选作参考时保留双方，避免覆盖新的选择。仍有有效原始副本的旧内容继续独立展示，不合并不同完整字节的实际文件。被替代资产与派生记录保留为历史，不删除照片、视频、备份或缓存，不迁移上传成功回执。

处理使用现有工作线程和事务；人脸处理或重建运行时不迁移关联。签名首次索引时生成，未变的内容和已恢复的修订复用，浏览不启动整库重扫。用户重新扫描由项目完成关联恢复，不依赖外部数据库修复脚本。

## Android 宝宝页紧凑顶部（2026-10-05）

宝宝档案显示 48 像素头像、昵称与当前年龄，右侧保留直接编辑入口；头像仍可点击更换，多个宝宝仍可点击昵称切换。出生日期可在档案和工具菜单中查看。新建档案、成长水印副本与水印显示开关收进右上角「相册工具」，沿用原操作和按宝宝保存的水印偏好。

全部、已加入、疑似与待核对保持单行，正常宽度均分按钮空间；根据实际文字宽度与系统字体缩放切换为横向滚动，不将筛选换成多行，也不压缩文字或 48 像素点击区域。全部月份与成长月份轴共用一行，月份范围或当前相册说明并入搜索、收藏及排序栏，长日期保留完整提示。待核对的解释点击说明展开，参考失效在工具菜单明确提示。

整理中仅显示已处理数量、总数、暂停与详情，阶段和完整进度在工具中查看；暂停可以继续，匹配与传输运行时保持原互斥规则。失败原因和仅重试失败仍可通过详情或工具查看，长通知单行展示并可展开。月份组标题减少上下留白，照片网格与完整原文件预览沿用原实现。本轮不改识别、收藏、传输、照片文件或存储结构。

## 电脑新照片自动识别队列（2026-10-05）

手机上传提交成功回执后，独立建立相册索引并将实际回执目标库加入自动识别队列；相册解码或人脸处理不延迟、撤销上传成功。复制导入与目录扫描结束后也将明确目标库的待分析内容排队，全局扫描只沿用当前库作为自动分析范围，不自动扩大到全部历史目录。切换照片库不会把已有接收批次的后续照片分配给新库。

队列保存在现有本机记录中，不增加数据库表或 IPC 方法。短时间内的多张照片合并唤醒，扫描、导入、缓存匹配或人物分析运行期间保留待处理目标；任务结束后自动接续，只分析尚未处理且仍获授权的内容。已完成缓存继续复用，单项失败不因后续接收、页面刷新或重启自动重试，人工加入和排除优先。应用启动恢复原队列及当前库尚未处理内容，停用库的队列等待重新启用，未完成的人脸重建仍需用户明确继续。

模型初始化由服务共用，自动识别不依赖打开图库或宝宝页；关闭应用清理唤醒计时器并保留未处理队列。仍要求宝宝开启自动匹配并持有有效本机参考，关闭开关后不继续启动新分析。现有强匹配、疑似候选、人脸特征、本地模型与原图预览规则保持。

本轮限定电脑自动识别队列。未添加文件夹监听，外部复制的新照片需要点击「重新扫描」，扫描结束后自动接续识别；手机仍沿用现有本地整理时机。原文件、归档副本及上传回执均保留。

## Android 相册搜索、收藏与宝宝待核对（2026-10-05）

普通相册将月份、搜索、收藏和排序集中在一行工具栏，搜索由明确点击展开，输入停顿 300 毫秒或提交后执行查询；搜索框清空恢复当前月份和类型，收起搜索同时清空关键词。文件名按字面包含查询，不将引号、百分号或下划线当作 SQL 或通配符。搜索、月份、媒体类型和收藏 ID 一起交给系统相册数据库计数与分页，未加载媒体同样参与筛选，仍只为可见项生成缩略图，不读取整库原文件。日期按最新或最早排列，同日期使用系统 ID 稳定分页，日期未知项放在末尾。

普通原文件预览和宝宝原文件预览均提供收藏爱心，两页共用本机媒体 ID 与版本记录；编辑后的新内容不继承旧版本收藏。仅收藏筛选重新查询全部已授权范围，旧版本收藏或权限范围外的项目不混入结果。存储成功后更新界面，写入失败保留此前状态并提示。升级时沿用旧手机索引已有收藏，后续取消不会因旧索引字段再次恢复。收藏沿用 SQLite 偏好记录，不增加表或系统相册写入权限，不随电脑连接同步。

宝宝相册增加「待核对」及数量，与全部、已加入、疑似并列；范围为当前手机已整理且仍被记录为授权的媒体，尚未完成整理时继续显示进度，不能将该数量解释为整个系统相册的完整识别覆盖。没有检出人脸、尚未分析、识别失败、缺少有效参考、关闭自动匹配或相似度不足的项目分别显示原因，旧自动排除也可核对。已加入、疑似和用户明确选择不是宝宝的媒体不混入待核对。打开原文件后沿用是宝宝、不是宝宝及明确选脸设参考操作，人工归属优先，不重新识别已完成媒体；确认后从待核对移入相应集合。

宝宝列表支持相同的文件名搜索、日期排序与收藏筛选，沿用当前宝宝、归属和成长月份，预览序列与实际筛选顺序一致。普通相册搜索、排序或收藏变化时保留当前电脑保存状态筛选，核对、补传与全选只作用于当前查询范围；切换月份、类型或接收目标重新建立对应范围。查询变化失效迟到分页和核对结果。原图预览、照片归档字节、水印显示与副本导出继续沿用既有规则，本轮不添加跨端宝宝记录同步、人物合并或水印原尺寸导出。

## 手机相册查看传入与补传状态（2026-10-05）

已配对电脑的普通相册提供「核对电脑」，核对范围为当前媒体类型、月份及已授权系统媒体。核对按页读取媒体属性并逐项计算或复用完整内容指纹，复用原有接收端求证、暂停、后台停止和迟到结果隔离流程；首次浏览仅恢复首屏本地记录，不自动读取整库原图。筛选读取所选范围后续分页，不将首屏无匹配当成整个范围无结果，缩略图仍只为可见媒体生成。

常驻筛选为「全部 / 已传入 / 未传入 / 需补传」。已传入仅指当前目标照片库有成功回执且电脑原文件仍完整；未传入指登记范围已完成核对且未找到相同原文件；需补传指当前库历史成功回执对应位置明确缺失或内容已改变。其他授权目录找到原文件时，在全部中标为「电脑其他目录已有」，仍可通过上传确认选择另存当前库。尚未核对、扫描不完整和无法读取不算未传入，也不算文件丢失，仅在全部与详情中说明。

电脑核对返回当前有效回执、历史回执及文件核实结果；读取失败后再次确认根目录，外接盘断开或身份变化不能判作文件缺失。手机保留同一内容的历史回执，编辑后的新内容、切换电脑或目标库不继承旧结论。旧接收端不能明确证明丢失时保留无法核实状态。数据沿用现有记录的 JSON 扩展字段，不改数据库结构、系统权限或依赖。

照片角标和预览中的「备份信息」展示目标、实际保存记录、其他目录位置、最近核对时间与失败原因；离线明确显示最近结果。未传入筛选提供「上传未传入」，需补传提供「补传缺失」，确认前再次核对当前目标与原文件。补传默认在当前库重新保存完整原文件，旧历史、损坏文件及其它目录副本保留；批次日期、归档路径和成功回执继续使用原传输规则。

## 电脑宝宝档案集中管理人脸参考（2026-10-05）

「宝宝相册 → 编辑档案」在自动匹配设置下显示人脸参考数量、参考照片缩略图及查看、移除操作，每个宝宝仍最多二十个参考。宝宝头像独立设置，选择或移除参考不改写已经选定的头像。移除先修改档案草稿，保存后更新参考并沿用原匹配范围；取消、关闭及 Escape 保留原参考与手工相册归属，原媒体文件均保留。

参考列表按宝宝已保存的媒体标识读取全部仍授权目录中的参考，不继承成长月份、照片搜索、当前已加载分页或人工相册归属，读取失败可以重试。无授权或原文件不可用时保留参考记录并提示；原照片可读但旧人脸失效时提示重新选脸。缩略图读取失败仍可查看原图，原图预览复用现有完整分辨率预览与授权媒体接口。查看时暂时隐藏档案，返回恢复未保存草稿；不沿普通相册顺序切换到无关照片。

「保存并添加参考」先校验和保存档案，再清除旧筛选进入当前库已有的参考选图与逐张选脸流程，首次建档也可直接进入。保存失败留在档案中保留草稿供重试，选脸仍需明确选择宝宝对应的人脸，已保存参考继续保留。普通照片预览中的「确认并设为参考」以及原人物查找入口继续可用，不新增媒体删除能力、数据库结构或系统访问接口。

跳转参考选图时取消旧搜索的延迟刷新，避免关闭刚打开的选脸或档案。成功写入后主动读取新状态，并丢弃写入前的后台轮询回执，添加参考后立即重新打开档案也能显示新参考。

## 手机年份选择按媒体日期范围（2026-10-05）

## 无脸照片与视频补检（桌面）

「补检漏识别」处理已经分析成功、没有保存任何人脸且尚未完成当前补检策略的媒体，不重复检测已有正常人脸缓存。宝宝成长相册提供紧凑入口，人物及参考页也可发起；当前库入口固定当前库，宝宝结果入口沿用当前选择的当前库或全部仍授权目录范围。补检计数与范围一致，运行中禁止重复发起，进度及单项失败仍从顶部处理记录查看。不在启动或轮询时自动对旧图库进行补检。

照片保留 0.75 的检测阈值。原方向没有检出脸时复用本地已解码像素，追加 90°、180°、270° 检测；先矫正 EXIF 方向，补检框逆映射回实际原图方向，跨角度去重。正常方向已有结果时保持原行为；这项策略不保证补出合照中部分漏掉的人脸，也未提取动态照片内嵌视频。

独立视频补检按时长增加抽样，至少 3 帧、最多 48 帧，目标间隔约 2 秒，超过上限时均匀覆盖时长；这是有限抽查，不能表述为逐帧完整识别。时长未知先尝试本地探测，仍未知仅检查起始帧，保留结果并记录覆盖不完整的失败原因，不标记补检完成。逐帧保存完成标记，失败重试重新探测时长，只处理未完成帧。

普通视频分析在有效时长内至少均匀检查 3 帧、最多 8 帧，约 3 秒的视频也检查首段、中段和尾段，避免只有中间画面未检出人脸就保存零脸结果。帧时间点与完成标记保持一致，失败重试复用成功帧；补检 48 帧上限及未知时长只尝试起始帧的规则保留。新分析与用户明确发起的人脸重建采用新策略，既有完成缓存不会因浏览自动重跑。有限抽样仍可能漏过极短暂的出现。

补检人脸保存「需要确认」标记，即使相似程度较高也只产生宝宝疑似结果，不自动创建人物分组；普通看图不画框，查看信息或明确选脸时显示补检标识。正常强匹配仍沿用原规则，人工加入、排除及参考保持优先。补检完成保存策略版本，失败或中断保留补检状态，既有「仅重试失败」可继续。不改数据库表结构，不改写或删除来源媒体。

## 成长水印（桌面 0.4.17、Android 0.4.3）

沿用现有真实预览与副本导出能力，默认「简约成长」两行排版：主行加粗成长年龄，次行以约 60% 字号显示 `YYYY · MM · DD`。默认白字、左下、短边 4% 边距；字号按照片短边 1000px 为基准缩放，四角均保留完整文字，浅背景可开启局部淡暗底。横竖照片、预览与导出使用相同排版规则。

内容模式互斥：自动成长在未满一个日历月时显示「出生第 N 天」，之后按完整日历月和余天显示，满一岁后转为年、月、天并省略零值；准确周年边界当天显示「X 岁啦」。出生天数模式始终显示「出生第 N 天」，出生当天为第 1 天。月底及闰日出生沿用目标月末的日历边界，不使用 30 天或 365 天换算。

宝宝照片预览与多选工具栏提供「成长水印」直达入口。桌面用大图与紧凑侧栏，手机使用照片主体与下方简短控制；默认只显示模式、位置与保存，昵称、日期开关、字号、颜色、透明度和淡暗底收进更多设置。参数调整自动刷新真实预览，迟到响应不覆盖新照片，取消与返回保留原相册位置、选择和照片预览。

宝宝相册增加「自动水印」显示开关，默认开启，按宝宝保存本机偏好，缩略图与大图共用同一开关。已加入宝宝相册且拍摄日期可靠的照片在开启时叠加成长文字及日期，关闭时显示无水印画面，切图与重开预览保持设置。疑似、待核对、视频和日期不可靠的照片不显示确定年龄。浏览叠加不调用图片生成或导出，不写副本，沿用虚拟图库只渲染可见照片；选人脸和设置参考时隐藏叠加，大图缩放与旋转沿用同一图片坐标。手动「成长水印」仍负责样式编辑和单张、批量保存副本，显示开关与人物自动识别互相独立。

只使用已确认归属与可靠拍摄日期的照片。文件创建日期只供核对，不直接计算月龄；日期早于生日、来源不可用、视频和未确认归属逐项显示原因。桌面水印仍限定当前照片库，每批最多 100 张；手机使用本机已授权照片。批量中单张无法解码或导出失败记录原因后继续，保存环境失效明确报错；成功与失败副本都不覆盖、不删除原媒体。照片导出为 JPEG，桌面保留原尺寸，手机沿用最长边 4096 像素上限。视频水印与成长拼贴留待后续。

## 扫描预计时间与响应优化（桌面，2026-10-04）

扫描与导入预扫描先仅遍历目录统计照片、视频文件数量，完整统计后按本轮实际处理速度显示预计剩余时间及已用时间。统计阶段与初始样本不足时显示正在估算；目录不可完整读取、旧任务缺少计时或扫描发现超出统计的新文件时保留未知总量。处理中进度不提前满格，完成前的目录核对显示正在收尾；时间采用分钟约数，会随文件大小和实际速度调整。

图库索引最多同时处理两个文件，同内容文件串行建立索引，继续使用完整 SHA-256 与大小去重。扫描进度最多每半秒保存一次，媒体记录、回执和失败原因仍按原规则持久保存。首批未填满且用户未滚动、选择或预览时，最多每四秒刷新已扫描结果；已有浏览位置与选择保持不变。

## 桌面 0.4.6 扫描与失败明细（2026-10-02）

扫描与导入逐项隔离文件错误：读取失败、预扫描后大小或内容变更、复制失败，记录当前项后继续其他可用媒体。目录授权或配置失效、来源与目标为同目录或父子目录，以及任务关闭仍中止整批，不绕过目录安全检查。重试保留原计划日期与目标，已变更的单项需要重新预扫描；原媒体、已保存文件及失败副本均保留。

使用现有通用记录机制持久化每条跳过位置与中文原因，界面在任务记录内按每页 20 条查看完整明细，不把任务最后进度文件名当作失败原因。旧任务只保留的前 20 条无法补出其余历史细节，明确提示历史样本限制。结果区分成功、跳过与整批中断后尚未处理；已知导入计划可统计未处理数量，未知总量的目录扫描不伪造完整总数或 100% 进度。

## 桌面 0.4.5 跨场景人物分组与合并（2026-10-02）

旧人物分组只与该组首次人脸特征比较，使用 0.5 的强匹配阈值，容易将不同角度或光线下的同一个人拆开。新增媒体识别改为每组使用最多 8 个互补样本，优先不同照片，并在本轮识别过程中纳入新发现的人脸。仍要求最佳相似度至少 0.5，且与次佳候选的差距至少 0.06；还必须与该组原人物参考或人工确认合并的原参考达到至少 0.363 的相似度。自动加入的样本不能绕过这项可信参考支持，避免相似样本逐步串联导致人物归属漂移。证据不足时建立独立组，不为减少组数盲目合并。

原人物参考的支持基准使用 0.363。该值来自 OpenCV SFace 在 LFW 的公开校准结果，不代表本项目或婴儿照片的实测准确率，也不替代本项目 0.5 的强匹配阈值；官方在其他数据集给出了不同阈值。[OpenCV 人脸检测与识别文档](https://docs.opencv.org/4.x/d0/dd4/tutorial_dnn_face.html)

同一照片中的不同人脸不能自动归到同一人物；视频按分析帧做此排他检查，允许同一个人在不同帧重复出现。已经完成的识别缓存继续复用，不自动批量重写或重新分组旧数据。已有拆分由用户核对后合并，避免一次升级改变整个图库的人物归属。

人物卡片提供「合并」入口。用户从来源卡片打开紧凑对话框，查看来源头像，在当前库人物头像列表中选择目标，最后点「确认合并」。目标选择、搜索、查看更多及错误重试沿用 V2 的紧凑样式；提交失败在对话框内提示原因并保留目标。人物分析运行期间禁止合并；两组曾在同一照片或视频同一分析帧共现时也拒绝合并。

确认后仅在来源人物记录保存指向目标的别名关系，读取时解析最终人物，显示名称沿用目标；此共享关系跨库生效。历史人脸编号、原始人脸特征、宝宝参考、人工相册归属和媒体文件保持原样。人工合并的原人物参考作为可信锚点帮助后续新增媒体识别，自动加入的样本不升级为新的可信锚点。

本节仅更新桌面 0.4.5，Android 保持 0.4.1。本版不承诺跨场景识别全部正确，尚无真实用户图库准确率结论；构建与具体场景验证见 [验收记录](verification.md)。

## 1. 产品定位

手机选择照片，通过同一局域网直接发送到电脑，在 App 内清楚区分哪些照片已经上传、哪些仍需上传。电脑可以通过网线连接路由器，手机通过 Wi-Fi 连接，只要双方网络可达即可，不要求都使用 Wi-Fi。

建议名称：**近传**。第一版面向个人使用，支持 Android 手机发送、Windows 电脑接收，原图传输，不依赖云端账户或中转服务器。

最重要的约定：**已上传表示指定照片版本已收到指定电脑、指定相册库的保存回执**。发送进度到 100% 只表示字节发送结束，不能直接显示成功。

## 2. 使用流程

1. 电脑启动近传，第一次使用时选择保存目录，显示配对二维码。
2. 手机授权读取照片，扫描电脑二维码完成配对；二维码包含局域网地址、接收端身份、公钥指纹和短期配对令牌。
3. App 显示照片网格、当前接收电脑及上传状态。可按相册、日期、上传状态筛选，选中几张或选择全部待上传。
4. 手机先与电脑核对内容指纹：当前目标库已有完整文件时返回对应回执；仅在其他历史目录发现相同内容时提示「电脑已有」及跳过选项，其余文件进入上传队列。
5. 电脑接收至临时文件，验证大小和 SHA-256，完成落盘并提交接收记录。
6. 手机收到回执后显示「已上传」，电脑列表显示「已保存」。断线时保留队列、临时文件和已确认偏移量。
7. 再次打开 App 时恢复历史记录，发现新增或编辑后的图片，并与已连接电脑核对待确认任务。

状态角标显示在本 App 的相册页面，不修改 Android 系统相册的界面或原图。

### 3.3 多个目录与历史图片核对

区分两类目录，均在 Windows 端由用户选择并登记：

- **历史扫描目录**：例如 `D:\以前的照片\`、`E:\旅行\`、`E:\手机备份\`。允许递归扫描普通子目录，计算内容指纹并记录真实位置；仅建立索引，保留原目录结构。
- **上传目标目录**：例如 `D:\照片归档\`、`E:\工作照片\`。每个目标对应独立归档库，手机上传时从已授权列表中选择一个；本次批量上传不会同时写入所有目录。

同一路径允许兼作历史扫描目录和上传目标。注册父子目录重叠时按规范路径去重；第一版不跟随目录联接或符号链接越出授权扫描范围，避免重复遍历和意外扩大范围。

历史核对使用完整 SHA-256 与大小，与文件名和目录名无关。相同内容可记录多个文件位置；以前用其他方式复制的原图也可识别。压缩、裁剪或修改后的照片不算同一内容，不能仅凭外观自动跳过。

相册区分两种证据：

- **已上传到当前目录**：存在当前目标库的有效上传回执。
- **电脑已有 · 其他目录**：在一个或多个已授权历史目录发现完整相同文件。显示所在目录与最近核对时间，不伪造当前目标库的上传记录。

默认上传只处理未保存图片，历史重复项在确认页单列为「将跳过，电脑已有」。用户如希望当前目标目录也保留一份，可对这些项目选择「仍上传到此目录」。完成摘要分别显示「本次新保存」与「历史已存在」，避免误认为所有图片都写入了当前日期文件夹。

扫描进行中或有目录不可访问时，显示「尚未核对完」与覆盖范围，不能报告为完整扫描后确认的「未上传」。外接硬盘离线时保留历史记录并标记「目录不可用」；无法核实文件存在时不据此自动跳过新备份。

上传前再次确认用于跳过的历史文件可访问且索引未过期；文件大小、修改信息或文件身份变化时重新哈希。保留手动深度核验入口。仅凭旧数据库记录不能保证文件仍在。

### 3.4 按日期自动归档

上传确认页显示：目标电脑、目标目录、日期规则、各日期分组的张数和最终路径预览。日期规则支持以下选择，默认选择待用户确认：

| 日期规则 | 分目录行为 | 适用情形 |
|---|---|---|
| 照片拍摄日期（建议默认） | 同一批不同拍摄日期的照片分别进入对应日期目录 | 整理旧照片、按拍摄日查找 |
| 上传日期 | 按本批次开始时的归档日期保存 | 按每次传输的日期管理 |
| 手动指定日期 | 本批次使用用户选择的日期 | 为一次活动统一归档 |

示例：选择 `D:\照片归档\`，按拍摄日期上传三天的照片：

```text
D:\照片归档\
  2026-09-20\
    IMG_0001__a12bc34d.jpg
  2026-09-21\
    IMG_0002__b23cd45e.jpg
  2026-09-26\
    IMG_0003__c34de56f.jpg
```

目录不存在则在接收时创建，存在则继续归档且不覆盖同名不同内容。日期是存储位置规则，不是判断是否重复的依据；改变规则不会令已经保存的内容失去历史记录，也不会自动搬动旧照片。

时间处理约定：

- 拍摄日期优先读取有效原始拍摄元数据，其次使用可信媒体拍摄时间；缺失时采用来源创建日期并在确认页提示，两者均缺失时回退到冻结的本批次上传日期。
- 有时区信息的拍摄时间保留其拍摄地自然日期；没有时区的时间保留原始日期，不擅自按电脑时区跨日转换。
- 上传日期按接收电脑的配置时区，在批次建立时固定，并在开始前供手机预览。跨午夜传输、断点续传或重试不改变本批次路径。
- 手动指定日期直接保存日历日期，不受时区换算影响。
- 每张照片的 `archive_date`、日期来源、目标库与最终相对路径在会话建立时确定；修改默认设置只影响新批次。

## 4. 上传状态的准确性

### 4.1 状态模型

将「任务执行状态」和「保存回执」分开存储，不仅保存一个 `isUploaded` 布尔值。

| 显示状态 | 判定 | 后续行为 |
|---|---|---|
| 未上传 | 当前图片版本没有目标库的成功回执 | 可以选择上传 |
| 排队中 | 已加入持久化队列 | 等待传输 |
| 上传中 | 正在传输字节 | 显示字节进度，可暂停 |
| 校验中 | 电脑已收齐字节，仍在检查并保存 | 不能计入成功 |
| 待确认 | 可能已保存，但回执丢失或结果不明 | 优先查询电脑，避免直接重传 |
| 已上传 | 存在目标库针对该内容的持久化回执 | 显示保存时间和目标 |
| 电脑已有 | 授权历史目录中存在完整相同内容 | 显示实际位置，可跳过或另存到当前目标 |
| 未核对/目录不可用 | 历史扫描未完成或已有文件所在目录无法访问 | 不宣称已完成核对，不据此自动跳过 |
| 已暂停 | 用户暂停任务 | 保留进度，等待继续 |
| 失败 | 可确定未完成，或服务端明确返回失败 | 显示原因并允许重试 |
| 需重新上传 | 核对发现电脑文件缺失或已损坏 | 保留历史，提供补传 |

图片角标是面向用户的摘要；任务队列内部还可记录哈希计算等阶段，不必全部展示为相册筛选项。

### 4.2 标记绑定的对象

- 接收电脑使用持久化 `receiver_id`，不使用可能变化的 IP 地址识别电脑。
- 每个归档库使用独立 `library_id`，相同电脑的新库不继承旧库的「已上传」。目录迁移若保留库清单并完成验证，可保持同一库身份；仅选择新空目录则创建新库。
- 照片内容使用 `SHA-256 + byte_size` 标识。相同名字不同内容是不同文件；同一内容换名字不重复保存。
- 同一张本地照片的路径或 MediaStore ID 不是永久内容身份。缓存还需要修改时间、大小和媒体版本等失效信息；选中待传文件时验证当前内容，防止编辑后误用旧回执。
- 最终状态由 `(receiver_id, library_id, content_sha256, byte_size)` 对应的接收回执决定。

照片被编辑后视作新内容版本，需要重新上传。新旧版本的记录均可保留。

### 4.3 特殊情况

| 情况 | 处理 |
|---|---|
| 相同图片重复点击上传 | 接收端按幂等键恢复原会话或返回原回执，避免重复落盘 |
| 上传成功但响应丢失 | 手机进入待确认，通过会话或内容查询取回回执 |
| 换一台电脑/新建相册库 | 使用对应目标的状态，不能沿用旧目标标记 |
| 手机 App 被卸载 | 本地历史可能丢失；重新配对并按内容哈希核对，恢复可匹配状态 |
| 电脑文件被手动删除 | 已上传保留历史意义；再次核对发现缺失后显示需重新上传 |
| 电脑离线 | 展示最近一次成功回执及时间，不宣称实时检查过文件 |
| 文件同名不同内容 | 保存为不同文件，绝不覆盖 |
| 传输期间手机原图变化 | 中止该内容版本，重新读取并计算哈希后创建新任务 |
| 图片权限被撤回/仅部分授权 | 显示授权范围；不可访问的任务暂停并说明原因，不视为照片已删除 |
| 可用空间不足或目录不可写 | 明确失败且不生成成功回执，保留手机原图 |

「已上传」是历史成功记录，不等于持续备份保证。电脑在线时可执行快速存在性核对；深度检查再读哈希。文件监听仅用于加快发现变化，不能代替启动/重连时的核对。

## 5. 推荐技术方案

以当前确定的 Android + Windows 范围，采用 Flutter 手机客户端、Electron 桌面端和内嵌接收服务，避免额外部署服务器。

| 部分 | 技术选择 | 职责 |
|---|---|---|
| 手机 UI | Flutter + Dart（首期 Android） | 相册网格、状态筛选、设备和任务界面 |
| 手机媒体访问 | Flutter 插件/平台通道 → MediaStore + ContentResolver | 读取已授权照片和原始内容流 |
| 手机记录 | SQLite（Dart 数据访问库待业务实现时引入） | 照片索引、配对目标、任务与回执 |
| 手机传输 | Dart 流式 HTTPS 客户端 + 必要的 Android 后台适配 | 文件读取、哈希、分块续传与回执核对 |
| Windows UI | Electron + Vue 3 + TypeScript | 接收界面、目录选择、图库与托盘 |
| 电脑接收服务 | Node.js HTTPS，生命周期由 Electron 主进程管理 | 配对、鉴权、流式接收、查询和状态确认 |
| 电脑数据 | SQLite + 本地文件目录 | 内容清单、任务状态、文件与回执 |
| 设备发现 | 首次扫码；重连 mDNS/DNS-SD，可回退手动地址 | 发现已信任电脑，不把发现结果直接当作授权 |

手机 UI 和业务逻辑采用 Flutter + Dart；系统相册与后台传输通过插件或 [平台通道](https://docs.flutter.dev/platform-integration/platform-channels) 接入。Flutter 构建 Android 仍需 [Android SDK 与工具链](https://docs.flutter.dev/platform-integration/android/setup)。桌面端采用 Electron，由预加载桥接限定界面的系统访问能力，参见 [Electron 预加载脚本](https://www.electronjs.org/docs/latest/tutorial/tutorial-preload) 和 [安全边界](https://www.electronjs.org/docs/latest/tutorial/security)。

进程结构：

```text
Flutter App（Android）
  相册 UI → 照片索引 → 持久化上传队列 → HTTPS 传输客户端
                            ↓
                         SQLite 记录

              同一局域网：认证后的 HTTPS

Windows 桌面程序
  Node.js 接收服务 → 会话/偏移管理 → 临时文件 → 校验 → 最终图片
                            ↓                       ↓
                        SQLite ← 接收回执/崩溃恢复日志
                            ↓
                   IPC → Vue 接收界面与图库
```

第一版由一个 Electron 应用管理本地服务，界面在隔离的渲染进程中运行，通过有限 IPC 与主进程交互；文件扫描和哈希任务放到工作线程，避免阻塞主进程。先不拆微服务，UI 层不直接操作文件或数据库。

### Android 约束

- Android 14 起可能只有部分相册访问权限，首页必须说明「仅显示已授权照片」，允许重新选择授权范围。不能把未授权图片计入「全部照片」。参见 [部分照片访问权限](https://developer.android.com/about/versions/14/changes/partial-photo-video-access)。
- 保持传输字节一致，不在传输路径压缩或转码；读取原始媒体内容可能涉及位置元数据权限。若无法取得未经系统脱敏的原始字节，应明确说明保留范围，哈希必须针对实际传输的字节计算。参见 [MediaStore 媒体访问](https://developer.android.com/training/data-storage/shared/media)。
- 用户点击开始的大批量任务，在 Android 14+ 评估采用 UIDT 任务并显示通知；较早版本采用符合平台约束的前台传输服务。第一版不承诺杀进程后持续上传，任务恢复必须依靠持久化队列和服务端会话。参见 [用户发起的数据传输](https://developer.android.com/develop/background-work/background-tasks/uidt) 与 [后台传输选项](https://developer.android.com/develop/background-work/background-tasks/data-transfer-options)。
- 局域网不一定能访问互联网，调度与网络判断不能要求公网连通才能上传。支持目标局域网可达即可，按实际 Android 目标版本适配局域网权限。
- mDNS 可能受路由器隔离、组播或网络配置影响，保留扫码/手动地址入口；地址回退只能解决发现问题，不能穿透网络隔离或防火墙。参见 [Android NSD](https://developer.android.com/develop/connectivity/wifi/use-nsd)。

## 6. 传输协议与可靠性

### 6.1 配对与连接

1. Windows 为安装实例生成稳定接收端 ID 和本地 TLS 身份，配对界面显式启用短期配对窗口。
2. 手机扫描二维码，取得预期证书/公钥指纹，通过指纹校验建立 HTTPS 连接；不全局关闭证书验证。
3. 使用短期、一次性随机配对令牌换取单设备访问凭据；配对令牌过期或使用后失效。
4. 后续使用已保存的接收端身份核验设备，即使地址变化也不信任陌生设备。证书身份变更时要求重新配对。
5. 手机凭据放系统安全存储，电脑凭据按系统保护机制保存；日志不记录令牌。支持电脑端撤销单个手机授权。

该流程在二维码可直接扫描的前提下足够简单；若后续提供短数字配对码，需要额外防猜测、限速和双方确认机制。

### 6.2 接口草案

下列接口是待实现的协议约定；除配对入口外均需认证，所有资源必须校验所属设备/库，不能凭可猜测的 ID 访问。

| 方法与路径 | 关键输入 | 返回/语义 |
|---|---|---|
| `POST /v1/pair` | 一次性配对令牌、手机身份 | 设备凭据、receiver_id、library_id |
| `GET /v1/receiver` | 已配对凭据 | 接收端身份、手机获准使用的目标库列表、默认库、日期规则、能力、是否接收 |
| `POST /v1/assets/check` | 当前库、有限数量的哈希与大小 | 当前库回执、授权历史目录匹配项、扫描覆盖状态/需上传/文件缺失/目录不可用；区分回执和历史证据 |
| `POST /v1/batches` | 目标库、日期规则、可选指定日期 | batch_id、冻结的归档时区/上传日期/规则；按照片元数据提供路径预览所需信息 |
| `POST /v1/uploads` | 幂等键、batch_id、库、哈希、大小、文件名、媒体元数据 | upload_id、固定归档日期与相对路径、已确认 offset，或当前目标库已有回执 |
| `GET /v1/uploads/{id}` | upload_id | 服务端确认偏移、阶段，已完成则返回回执 |
| `PUT /v1/uploads/{id}/content?offset=n` | 单块字节、期望偏移 | 持久化后的 confirmed_offset；偏移冲突返回 409 |
| `POST /v1/uploads/{id}/complete` | 预期大小与哈希 | 校验并提交后的回执；重复调用返回同一结果 |

第一版可从 2 个文件并发、每块 4 MiB 开始，再根据真机吞吐和内存实测调整；这些是初始参数，不是性能承诺。每个文件按顺序提交块，接收端对同一会话串行写入。

接收端流式读取请求体，不将整批原图载入内存。块尺寸、单文件尺寸、任务数和空闲磁盘空间都有限制；不使用客户提交的绝对路径。

### 6.3 保存与回执

```text
1. 创建/恢复上传会话与临时文件
2. 按已确认偏移接收字节，持久化可恢复进度
3. 收齐后重新计算 SHA-256，核对字节大小
4. 记录待提交状态与预定最终路径
5. 在同一文件卷内完成临时文件刷新与原子重命名
6. SQLite 事务提交文件记录、来源信息和成功回执
7. 返回含 receiver_id、library_id、hash、size、receipt_id、saved_at 的回执
```

文件系统和 SQLite 不能组成同一个原子事务，因此必须有步骤 4 的恢复记录：若步骤 5 后崩溃，启动时校验最终文件并补齐步骤 6；若文件尚未完成则继续会话。恢复完成前不返回成功。数据库有记录但文件不存在时标记缺失，禁止仅凭记录去重。

客户端收到回执并提交本地记录后才更新「已上传」。若响应丢失，通过会话状态或内容清单核对；不能靠重新发送整张图片猜测上次结果。

暂停/断网保存偏移，重连时以服务端确认偏移为准。HTTP 写入结果不明时先查询会话，不假定块未写入。相同内容并发完成时，由库内内容唯一约束和提交锁确保只产生一份有效文件。

## 7. 最小数据模型

### 手机端（SQLite）

| 表 | 关键字段/约束 |
|---|---|
| `local_assets` | 本地记录 ID、media_uri、volume、媒体 ID、大小、修改时间、当前内容哈希、权限可访问性 |
| `receivers` | receiver_id、名称、可信公钥指纹、地址提示、凭据引用 |
| `libraries` | library_id、receiver_id、库名称与目录展示信息、可选日期规则 |
| `upload_batches` | batch_id、receiver_id、library_id、date_mode、固定上传日期、归档时区、可选手动日期 |
| `upload_tasks` | task_id、batch_id、local_asset_id、目标库、archive_date、日期来源、预期 hash/size、服务端 upload_id、幂等键、阶段、confirmed_offset、错误信息 |
| `upload_receipts` | receiver_id、library_id、hash、size、receipt_id、saved_at、last_checked_at、presence_state；目标+内容唯一 |
| `existing_matches` | receiver_id、hash、size、匹配位置标识与展示名称、最后核对时间、可访问状态；独立于上传回执 |

本地资产代表手机的一条照片记录，内容哈希代表实际字节；多条本地照片可以指向同一个内容，因此不能只以哈希作为相册项目主键。

### Windows（SQLite）

| 表 | 关键字段/约束 |
|---|---|
| `libraries` | library_id、根目录、库身份与创建时间 |
| `scan_roots` | root_id、规范根目录、目录展示名、授权范围、扫描阶段、最近扫描时间、可访问状态 |
| `indexed_locations` | location_id、root_id、相对路径、hash/size、文件修改信息、文件身份、最近核验时间、存在性；位置唯一、内容可对应多个位置 |
| `paired_devices` | sender_id、名称、认证凭据校验信息、撤销状态 |
| `upload_batches` | batch_id、sender_id、library_id、date_mode、固定上传日期、归档时区、可选手动日期 |
| `upload_sessions` | upload_id、batch_id、sender_id、library_id、archive_date、日期来源、hash/size、幂等键、确认偏移、临时/最终相对路径、阶段、更新时间 |
| `stored_files` | file_id、library_id、完整 hash、size、相对路径、保存时间、存在性；库+内容唯一 |
| `asset_sources` | file_id、sender_id、原始文件名、媒体来源元数据；保留重复来源 |
| `receipts` | receipt_id、file_id、sender_id、关联会话和确认时间 |

主进程通过经过约束的 IPC 事件刷新 Vue 界面，不增加专门的 WebSocket 服务。网络协议用版本前缀，第一版只实现一套能力。

## 9. 验收标准

| 场景 | 通过条件 |
|---|---|
| 首次发送 100 张已授权照片 | 每张完整保存；手机成功计数与电脑有效文件一致；内容哈希匹配 |
| 再次发送同一批 | 已有完整内容返回回执，不增加重复文件 |
| 同名不同内容 | 两份内容均保留，不覆盖 |
| 编辑一张已上传图片 | 新版本变成待传，旧版本记录不误用于新内容 |
| 传输时断开网络 | 已确认成功的照片保持成功；未完成任务可恢复；不产生假成功 |
| 电脑已保存但手机未收到响应 | 手机查询恢复成功状态，不重复落盘 |
| 电脑校验或重命名期间崩溃 | 重启后恢复记录与文件一致，不生成损坏的成功文件 |
| 手机杀进程后重开 | 已完成记录保留；未完成任务可查询并继续 |
| 磁盘满/目录不可写 | 失败原因明确，没有成功回执，没有覆盖旧文件 |
| 部分相册权限 | 只显示已授权照片，并提供管理授权入口 |
| 电脑外部删除文件 | 核对后显示需重新上传，并可补传 |
| 切换接收电脑或新库 | 根据目标重新判断状态，不串用原目标回执 |
| 历史原图分布于多个目录 | 全部授权目录完成扫描后可匹配原图；同一内容多个位置均可记录；不改动原文件 |
| 原图只在其他历史目录存在 | 显示电脑已有及位置；默认跳过时不产生当前库回执；显式另存时生成当前库回执 |
| 外接盘离线/扫描尚未完成 | 提示覆盖范围和不可用目录，不把旧索引当作当前可用副本 |
| 一批照片跨多个拍摄日期 | 按所选规则分入正确的日期目录，并与上传前预览一致 |
| 按上传日期传输跨过午夜 | 同批次路径不变，重试和续传不创建新的日期分组 |
| 照片没有可靠拍摄时间 | 明确提示回退规则，归档日期可在上传前检查 |
| 未配对设备请求 | 无法上传、查询哈希清单或获取原图 |
| 无公网的可达局域网 | 可以配对、传输和查询状态 |

## 10. 设计原则

- **KISS / YAGNI**：两个本地程序、一个由桌面应用管理的接收服务；先做好图片与可靠状态，不引入账号、云服务或微服务。
- **DRY**：同一套内容身份和回执规则用于相册角标、去重、补传和任务恢复。
- **单一职责与依赖边界**：相册索引、传输队列、接收会话、文件存储和 UI 分开；关键业务依赖媒体/存储/网络接口，便于故障注入验证。
- **验证状态而非按钮**：重点测试断网、响应丢失、文件修改和崩溃后的真实文件与记录一致性。
