# 近传 · Jinchuan

Android 宝宝整理启动后独立于当前页面运行，切到相册、传输或普通预览继续处理；手工暂停保留完成数量，继续前核对当前授权媒体、原文件状态与已完成缓存，仅对剩余、新增或变化项计算指纹和分析。进度与失败重试范围保存在现有本机偏好中，重开恢复计数，旧版已完成分析也可复用；暂停期间的当前项先结束并保存，再启动下一轮。进入应用后台或实际传输时保留进度暂缓，回到前台且传输结束后自动接续；手工暂停不会因前后台切换或传输结束自动恢复。

Android 普通相册与宝宝相册的原图预览采用全屏画布，按原始比例完整适应屏幕，点图可收起或恢复工具。宝宝照片不再常驻底部按钮与遮罩，顶部保留返回、收藏和更多；是宝宝、不是宝宝、设为参考、水印显示、照片信息与上传收进更多菜单，主动选脸、视频播放或处理状态才显示底部所需控件。普通相册底部仍为备份信息图标、宝宝整理与传到电脑一排。移除底部上一张、下一张切换栏，左右滑动提供跟手位移与平滑过渡，短滑和首尾回弹；放大、双指缩放和选脸不会误切图。水印副本从照片信息制作，完整原图与比例保留。

电脑图库在重扫或打开原文件发现变化时自动核对索引：仅修改文件时间且完整字节相同，继续使用原记录；JPEG、PNG、WEBP、HEIF 与 QuickTime 视频的编码数据和渲染属性一致时，按新完整指纹更新拍摄日期，保留收藏、人工宝宝归属、人物与参考人脸，旧记录保留为历史并收起失效卡片。旧版无内容签名时，仅从仍授权的原始副本或完整指纹校验通过的元数据备份恢复；无法证明内容相同时保留历史并提示「原文件已变化」。真正换图、方向变化、读取失败及目录离线分别处理。原媒体和上传回执不改写，WEBP 即使误用 JPG 后缀也按真实结构读拍摄日期。

Android 宝宝页顶部采用紧凑布局：头像、昵称、年龄与编辑入口合成一行，全部、已加入、疑似与待核对保持单行，窄屏或大字体时横向滚动。新建档案、成长水印及水印显示开关集中在右上角「相册工具」；月份选择和搜索工具减少重复行，整理进度仅显示计数、暂停与详情，让首屏多展示照片。

电脑接收新照片或复制导入完成后，自动将实际目标库的待分析内容加入本地人脸队列，无需切回图库或宝宝页。短时间批量传入合并处理，识别期间的新内容在当前任务结束后接续；队列随本机记录保存，重启继续未处理内容。仍需开启宝宝自动匹配并设置有效本机参考，停用目录或关闭开关时暂停，已完成缓存复用、失败项明确重试、人工归属优先。直接复制到文件夹的新增照片仍需「重新扫描」，扫描完成后自动接续识别；上传成功以保存回执为准，不等待人脸结果。

Android 相册与宝宝页支持文件名搜索、最新/最早日期排序和本机收藏筛选；点击放大预览中的爱心收藏或取消，两处共用同一份记录。普通相册在系统查询中筛选全部已授权媒体，搜索不限于已加载的照片。宝宝页新增「待核对」，可查看已整理范围中尚未分析、无脸、识别失败或相似度不足的媒体，打开原文件后确认是宝宝或不是宝宝。人工排除与已加入、疑似分别处理，核对不修改原文件或传输回执。

手机普通相册连接电脑后提供「核对电脑」及「全部 / 已传入 / 未传入 / 需补传」。已传入以当前照片库的有效保存回执与实际原文件为准；历史回执对应文件缺失或损坏时显示需补传，目录离线或读取失败仅提示暂时无法核实。点击照片角标或预览中的「备份信息」查看保存位置与核对时间；未传入和需补传支持按当前筛选范围批量上传，仍先核对并确认，不删除原文件。此功能需要手机和电脑接收端同时更新。

电脑宝宝相册的「编辑档案」集中显示人脸参考数量、照片缩略图与自动匹配设置。点击参考照片查看原文件，返回保留档案草稿；移除在保存档案后生效，取消保留原参考。「保存并添加参考」先保存档案再进入现有选图与逐张选脸流程，照片预览中的「确认并设为参考」继续可用。参考管理可查看其它仍授权目录中的参考，原照片、宝宝头像与手工相册归属保留。

手机相册和按月备份的年份选择按当前授权媒体的最早、最新日期生成连续年份，保留中间没有照片的年份，不再固定列出 1900—2100 年。选择框打开后只查询日期两端各一项，不枚举整库媒体；读取中显示提示，失败可重试。拍摄日期缺失时沿用系统入库日期，日期未知不影响年份范围。

大图库浏览与人脸模型加载分开：电脑先返回已有图库，同条件连续分页复用筛选和排序，记录或授权变化后更新。手机整理不提前生成整库缩略图，可见照片按需读取系统缩略图；大相册 JSON 编解码放到独立 isolate，扫描进度合并刷新。首轮完整内容校验和人脸推理仍需要时间，不能将首屏显示速度当作一万张照片全部分析完成。

桌面日常数据固定保存在用户目录的 `.jinchuan`，开发、预览和不同版本 EXE 使用同一份相册记录与缩略图缓存；升级不会要求重新导入。首次切换保留原记录并校验生成缓存，原照片不改写。缩略图读取失败提供明确的重试入口，重试只读取当前可视区，不重新扫描照片。

电脑扫描先完成照片与视频的完整内容索引，缩略图在浏览时按需生成，已有缓存继续复用。完整 SHA-256 采用有界大读块读取；相同内容且日期已确认的媒体复用已有元数据，未知日期仍可补齐。重扫时业务字段与位置未变化的资产保留原记录，避免重复落盘和使浏览缓存失效。人物匹配先核对可信参考，再比较有效候选的场景样本，保留原有门槛、歧义判断与归组顺序。索引提前完成不代表整库缩略图或人脸识别已经完成。

电脑端点击窗口关闭按钮或使用 Alt+F4 时询问「是否真的关闭近传？」，默认取消；确认后停止处理并关闭接收服务。

应用 Logo 已接入 Windows 可执行程序、窗口图标和 Android 自适应启动图标，同一份透明原稿生成各平台资源。Android 可分别构建沿用旧证书的调试升级包和使用正式证书的新安装包；私钥与密码仅保存在本机忽略目录。图标生成、正式签名初始化及构建命令见 [开发说明](../development.md#应用-logo-与-android-正式签名)。

Android 0.4.7 的宝宝相册只整理手机本地、当前已授权的照片和视频。宝宝档案、人脸参考、归属、拍摄日期与水印均在本机处理，不再随电脑连接同步，也不下载电脑原文件。移除「同步电脑相册」「取回原文件」入口；本机读取失败提示检查权限或重新选图，旧电脑记录和缓存文件保留但不混入宝宝相册。电脑连接只用于上传和备份核对。

Android 0.4.6 将宝宝人脸参考接成直接选图流程：从「管理人脸参考」选照片后自动检测，明确点选宝宝的人脸再保存并返回宝宝页；检测中显示进度，无脸可重试或换图。无效的旧特征缓存会重新检测，合照不会默认选第一张脸。

Android 0.4.5 修复大相册打开宝宝页时的 `Row too big to fit into CursorWindow`：分段读取已有照片索引，完整保留档案、人工归属、人脸参考和水印偏好；失败时显示读取阶段并提供「重新读取」，记录恢复完成后才开放建档和编辑。可覆盖升级，无需清空索引。按月备份同时支持整月展示和全选，缺少拍摄日期时用手机创建日期归档。

桌面 0.4.20 保留人脸重建前的宝宝结果供浏览，并标注「重扫前结果 / 重扫前疑似」，中断时顶部提供「继续重建」。人工确认与排除优先；完成后统一切换新结果，旧结果不作为自动水印、导出或手机同步的已确认归属。继续只处理剩余媒体，已完成的新特征保留。

人物页提供「重建人脸索引」：完整备份后清除当前库的旧人脸缓存，从原照片及视频重新检测，再统一归组。弱相似先待归组，后续清晰样本会重新判断；明确选定的宝宝参考用于跨场景匹配。原媒体、人工相册归属、日期、收藏和宝宝档案保留，可靠恢复不了的参考需重新选择。进度与跳过原因在顶部处理记录查看，普通启动仍复用已完成缓存。

电脑宝宝相册提供「待核对」：没有检出人脸、相似程度不足、尚未分析或识别失败的媒体都能查看并人工加入。低相似度只表示缺少匹配证据，只有明确选择「不是宝宝」才算人工排除；旧自动排除记录也可直接核对，无需清空索引或重新导入。已加入、疑似与待核对分别显示，正常成长相册继续混合展示已加入和疑似。

普通短视频人物分析至少均匀检查三帧，避免只抽到中间没有人脸的画面；普通视频仍最多八帧，补检仍最多四十八帧。新分析与明确重建使用新策略，已完成的旧缓存可通过补检或人脸重建更新，不在每次浏览时重复检测。

当前版本以 [桌面版本配置](../../apps/desktop/package.json) 和 [Android 版本配置](../../apps/mobile/pubspec.yaml) 为准；每次打包自动递增补丁版本，交付文件名包含版本号。本项目提供本地家庭照片与视频管理、宝宝成长相册，以及 Android → Windows 局域网原文件传输。桌面分为「照片与视频」「宝宝相册」「导入与归档」；手机分为「相册」「宝宝」「传输」。

成长水印采用两行排版：主行显示成长年龄，次行显示拍摄日期；默认左下白字，可选择「自动成长」或「出生第几天」，昵称、字号、颜色和淡暗底按需调整。出生当天算第 1 天，月龄按日历月计算，周年当天显示「几岁啦」。宝宝照片预览与多选提供直接入口；单张失败或日期未确认会显示文件名与原因，其余有效照片继续生成新的 JPEG 副本。原照片和失败副本保留，视频暂不导出水印。详见 [成长水印设计](../product-design.md#成长水印桌面-0417android-043)。

手机与电脑点开普通预览必须显示原文件，保持完整画面与比例，不用缩略图或压缩副本代替，不限制原图解码分辨率；只在显示时适应窗口或由用户缩放。读取或解码失败明确提示，不用缩略图冒充成功预览。缩略图可以缩小与裁切，性能优化不能牺牲预览质量。

宝宝相册的水印显示开关统一控制缩略图与大图预览，默认开启，沿用按宝宝记住本机选择的规则。预览中的开关修改同一份设置，切图、重开预览和重启应用均保留；关闭显示原图，开启只在原图上叠加文字，不压缩或改写原文件。只有已加入相册且拍摄日可靠的照片显示确定年龄；浏览叠加不处理原图、不生成副本，选人脸时隐藏。需要保存带文字的照片，继续从「成长水印」手动单张或批量导出。最新 Android 安装包与验证结果见 [验收记录](../verification.md)。

桌面 0.4.18 修复水印副本丢失拍摄日期的问题：新 JPEG 保存最终确认的拍摄日，再次导入按拍摄月份归档；手工修正日期优先，日期文字隐藏时也保留元数据。不复制原照片的定位、设备信息或旧方向标记。

桌面 0.4.16 的宝宝相册默认一起展示已加入与疑似，提供「全部 / 已加入 / 疑似」和明确的查找范围。预览可确认是或不是宝宝，选定具体人脸后设为参考；人工确认、自动匹配和参考标记分别显示。缓存匹配提供进度及未分析、失败、无脸、参考失效说明。图库只渲染可视区，收藏和归属确认局部更新，切模块恢复同库浏览位置；人物整理逐项审核，可看关联照片并在记录未变化时撤销本次整理。详见 [本轮体验优化](../product-design.md#桌面-0416-宝宝确认与大图库体验2026-10-02)。

Android 0.4.2 同样默认展示已加入与疑似，宝宝顶部提供档案编辑和独立的系统相册头像选择；预览支持左右滑动、按需查看信息，明确进入选脸后才标记人脸。整理提供暂停、继续、失败明细和仅重试失败，完成缓存继续复用。头像与本机参考不随家庭记录同步；构建及设备验证结果以 [验收记录](../verification.md) 为准。

桌面 0.4.15 修复预览工具与 Windows 原生窗口按钮重叠的问题，预览操作位于顶栏下方。「照片信息」使用可见文字，点击查看文件、日期及保存位置；「返回相册」只关闭预览。传输记录复用同一大图预览，提供按需信息和「返回记录」，实际回执与原媒体保留。

界面按 V2 总览与传输流程图实现。桌面默认打开图库，顶部常驻当前照片库名称和切换入口，切模块保持当前库。照片与视频按月份分组，可展开折叠，搜索和照片/视频筛选直接可见；宝宝顶部直接显示编辑档案、新建档案和更换头像，其余人物、收藏、多选、参考、水印按需从工具菜单进入。已记住的库离线或停用时保留选择并提示，不自动切换。详见 [当前照片库设计](../product-design.md#当前照片库与-v2-交互040)。

桌面 0.4.3 延续 0.4.2 的样式校准：56px 顶栏合并当前库与原生窗口按钮，搜索及筛选集中于照片工具栏，图标和配色按 V2 图统一。图库可选「最新在前 / 最早在前」，日期未知项均排在末尾；首批 50 项，向下滚动逐批追加，加载更多保留已选媒体。人物以真实人脸头像及数量卡片展示，点击查看该人物的媒体，命名单独操作；图片预览可以直接点检测到的人脸框或头像，选择宝宝参考。

桌面宝宝档案开启自动匹配并具有有效参考后，自动分析当前库尚未处理的媒体；完成结果复用，失败项只在明确重试时再次分析。关闭自动匹配后不继续自动分析，人工加入与排除优先，识别和相册归属不改变传输回执。详见 [0.4.3 图库与人物交互](../product-design.md#桌面-043-图库人物与自动整理)。

桌面 0.4.4 支持用几张宝宝照片查找相似人脸：「宝宝相册」→「用照片查找」→「选择参考照片」，每次最多选 20 张可用照片，再逐张点宝宝头像或人脸框保存，支持不同角度和成长阶段。可跳过单张，保存失败停留重试，关闭后保留已保存参考；每个宝宝最多 20 个参考，不静默替换旧参考。查找在本地复用全部有效参考的缓存特征，结果限定当前库，进入已加入相册或待确认结果，无结果和参考失效均明确提示。布局沿用 V2 紧凑样式；详见 [多张照片参考设计](../product-design.md#桌面-044-多张照片参考查找)。

桌面 0.4.5 改善新增媒体的跨场景人物分组：每组复用最多 8 个互补样本并随识别更新，保留强匹配与组内支持检查，同一照片或视频同一帧中的不同人不会被自动归为同组。已经拆开的同一个人，可从「照片与视频」→「人物」点来源卡片的「合并」，核对目标头像后确认；合并跨库生效，沿用目标名称，原人脸记录、宝宝参考、相册关联和媒体均保留。旧识别缓存不自动批量重分；详见 [人物分组与合并设计](../product-design.md#桌面-045-跨场景人物分组与合并2026-10-02)。

桌面 0.4.6 调整扫描与导入失败处理：单项无法读取、预扫描后内容变化或复制失败，记录原因后继续其他文件；目录授权或配置失效、来源目标重叠及任务关闭仍停止整批。新任务保存全部跳过位置与中文原因，处理记录每页查看 20 条，并区分成功、跳过和中断后未处理；旧任务未保存的明细无法恢复。扫描未知总量时不显示虚假 100%，同内容合并数单独说明，图库项数可能少于文件数。原媒体与失败副本保留，重扫由用户明确发起；详见 [扫描与失败明细](../product-design.md#桌面-046-扫描与失败明细2026-10-02)。

桌面 0.4.7 将人物头像查找改为按参考人脸比较整个已索引图库，跨越同人被拆开的分组；默认范围为全部仍授权的目录，也可限定当前库。相似结果按页追加，显示完整结果数及尚未分析、失败的覆盖情况，只供核对，不自动合并人物或加入宝宝相册。普通图库继续使用当前库，「全部媒体」清除旧人物、搜索和日期等筛选。照片与视频按月份展开、折叠；普通预览不显示人脸框，仅明确进入「选择宝宝人脸」时显示，参考队列仍逐张选脸。详见 [全局人脸查找与月视图](../product-design.md#桌面-047-全局相似人脸与月视图2026-10-02)。

桌面 0.4.8 修复月份折叠后停止自动加载的问题：折叠只影响展示，滚动继续按批加载后续媒体；「折叠全部」使新加载的月份也保持收起，展开单月不影响其他月份和已选照片。收起月份的缩略图延迟到展开时加载，复用已生成缓存，不重新扫描或识别人脸。详见 [折叠与连续加载](../product-design.md#桌面-048-折叠与连续加载2026-10-02)。

桌面 0.4.9 减少大图库分页时重复处理整库人脸特征，折叠全部先显示操作提示并回到顶部。图库直接提供「刷新列表 / 重新扫描」：刷新重读现有索引，重新扫描递归当前文件夹及普通子文件夹，扫描中断明确提示，现有识别缓存复用。宝宝查找统一展示已加入与待确认，候选卡片标明状态并需人工确认。详见 [分页与完整索引](../product-design.md#桌面-049-大图库分页完整索引与宝宝结果2026-10-02)。

Android 打开即直接读取已授权的系统相册，首批 60 项并随滚动分页，无需先导入、核对备份或识别人脸。点照片预览，点右上「选择」或长按进入多选；支持全选已加载媒体，分页、切模块和回到前台保留所选项，再确认传到电脑。视频保留时长与播放。电脑连接和按月备份位于「传输」，宝宝档案、参考、整理与同步位于「宝宝」的工具菜单。

桌面 0.4.10 将处理记录从图库底部移到固定顶栏：点击「处理记录」弹窗查看扫描、导入和人物分析的进度、失败原因及跳过明细。任务变化只更新按钮的运行数量或新记录提示，不自动弹窗；关闭后保留照片滚动位置、多选及月份折叠。详见 [按需查看处理记录](../product-design.md#桌面-0410-处理记录弹窗2026-10-02)。

桌面 0.4.11 重做放大预览：图片占据主体，文件信息默认收起；支持前后切换、滚轮缩放、放大拖动、适应窗口、100% 实际大小、旋转查看和全屏。切换沿用当前查询的日期顺序，末尾按需追加下一批；视频保留播放控制，宝宝选脸仍需主动进入。详见 [大图预览](../product-design.md#桌面-0411-大图预览2026-10-02)。

桌面 0.4.12 将编辑档案、新建档案和更换头像放到宝宝顶部栏。档案编辑器中可从当前照片库分页、搜索选择头像，保存后记住，取消保留原档案；头像独立于人脸参考，不要求先识别人脸，也不触发匹配。头像当前仅保存在桌面，手机同步共享档案时保留这项选择。详见 [宝宝档案与头像](../product-design.md#桌面-0412-宝宝档案与头像2026-10-02)。

桌面 0.4.13 统一浮层关闭：照片库、筛选、宝宝工具和设备菜单可点击外部或按 Esc 收起，打开新菜单会收起旧菜单。弹窗保留关闭、取消及遮罩关闭；预览信息面板可点击外部收起，多层预览按 Esc 逐层关闭。已发出的保存或合并继续完成，关闭只改变当前视图。详见 [浮层关闭交互](../product-design.md#桌面-0413-浮层关闭交互2026-10-02)。

桌面 0.4.14 修复歧义人脸不断新建人物组的问题：识别区分匹配、新人和待归组，分不清时保存人脸特征，人物页提供待归组照片入口。「整理已识别人脸」使用已有缓存生成合并方案，核对头像并明确确认后才应用；命名及人工合并人物保留，同图或同帧冲突不合并，原人脸、宝宝参考、相册归属和媒体保留。详见 [人物分组修复](../product-design.md#桌面-0414-人物分组修复2026-10-02)。

手机传输页按真实批次显示当前与历史任务，点批次查看文件列表，再点文件查看进度、固定目录、归档日期、回执和失败原因。新任务刷新电脑当前库，手机只查看目标；电脑切库后旧任务仍向原目录续传。字节发送到 100% 后继续等待保存回执，不提前标为成功。

Android 0.4.1 本轮调整 V2 样式：传输任务以浅描边卡片分组，暂停入口放在活动卡片内；宝宝待确认使用小数字徽标，视频显示时长角标，任务详情使用浅灰次按钮及清晰字号。本轮新增的桌面人物卡片、日期排序和自动分析交互未作为手机新功能交付。

当前库已有文件直接建立索引；其他电脑文件夹复制归档到当前库。照片与视频使用完整 SHA-256 和大小统一关联，相同内容共享识别缓存。普通图库、收藏、人物分组与水印使用当前库；宝宝结果可明确切到全部仍授权且可用的目录，人脸相似查找也有独立范围，数量、预览与打开位置使用相同范围。原文件保持原样。拍摄日期优先，缺失时使用源文件创建日期；月龄与水印要求确认实际拍摄日期。

复制归档的来源与目标必须互不包含，同目录及父子目录在界面和服务端均禁止。照片与视频没有删除能力；移出宝宝相册、取消收藏和移除人脸参考只修改记录，原文件、归档副本和水印副本均保留，失败导出的副本也不会自动删除。

宝宝档案支持出生日期、手工归类、多个参考人脸、本地人物匹配、待确认候选和成长时间线。照片月龄水印可预览并导出副本；视频支持原字节传输、封面、播放和有限抽帧人物查找。**视频水印暂不在本版范围内。** 两端可同步档案、人工归类与日期，手机缓存电脑缩略图并按需取回原文件。

人脸模型与媒体工具随发布程序分发，整理和识别不需要互联网。源码首次安装依赖与下载公开模型需要联网：`npm run models:setup`；之后两端均可离线使用相册，同步与传输仅需要同网段局域网。

0.2.0 已强制限制为同网段 IPv4 局域网传输；手机仅使用 Wi-Fi/有线连接，不回退移动数据。详细限制见 [仅局域网规则](../lan-only.md)。

Android 手机通过局域网向 Windows 电脑传送原图，核对多个历史目录，并按日期归档。手机使用 Flutter + Dart，电脑使用 Electron + Vue 3 + TypeScript。

保留真实相册、配对、HTTPS 传输、历史核对、持久化回执和断点恢复。交付为 Android 调试 APK 与 Windows x64 便携程序。独立的月份备份页选月后自动展示整月已授权媒体，可全选上传，缩略图按需加载；宝宝整理按需扫描已授权媒体并复用未变化的指纹与识别结果。有参考人脸时，首次进入宝宝页自动整理，切走可在工具菜单继续；相册首页不前置整库处理。详见 [使用说明](../user-guide.md)。

电脑端支持明确发起「补检漏识别」：只检查仍授权且可用、已有无脸结果而未完成本轮补检的项目。照片在原方向没有检出脸时，本地追加 90°、180°、270° 检测并把框还原到原图；视频补检增加有限抽样，最多 48 帧。补检人脸保留待核对标记，宝宝匹配最高进入疑似，不覆盖人工确认，也不自动批量重建人物。完成结果继续缓存，失败与中断可从「仅重试失败」继续；原媒体不改写。内嵌动态视频提取和同图部分人脸漏检仍不在这项补检范围内。

## 已实现

- 手机扫描二维码或粘贴配对信息；证书指纹固定，一次性配对信息有效 5 分钟。
- 系统媒体库直接按年月查询已授权相册，自动读完并展示整月，可全选筛选结果；连接后逐批自动核对所选月，独立显示整月已备份 / 未备份 / 待核对数量。
- 一键只上传本月已确认未备份的照片，排除待核对与其他已登记目录已有的原图。
- 电脑可配置多个接收目录、多个历史目录；以原图 SHA-256 和大小核对，改名仍能识别。
- 当前目录已保存的原图自动跳过；历史目录相同原图默认跳过，也可选择在本次目录另存一份。
- 按拍摄日、电脑确认的上传日或指定日期创建 YYYY-MM-DD 子目录；缺少拍摄日的截图或微信保存文件优先按手机创建日期归档，重试保持批次日期。
- 4 MiB 分块、偏移持久化、完整哈希校验、保存回执、暂停/继续、失败重试和任务取消。
- 目录、配对、任务和回执持久保存；电脑查看接收记录、图片预览、定位文件、撤销设备授权。

传输采用前台模式，手机切到后台会暂停，回来后手动继续。未实现持续后台传输或 mDNS 自动发现。当前不发布 iOS/macOS 版本。

## 启动开发

在项目根目录执行：

```powershell
npm ci
npm run models:setup
npm run dev
```

手机需要 Flutter 和 Android SDK：

```powershell
npm run mobile:deps
npm run mobile:dev
```

## 验证和打包

```powershell
npm run build
npm run desktop:test
npm run desktop:ui:test
npm run desktop:layout:test
npm run mobile:analyze
npm run mobile:test
npm run desktop:package
npm run mobile:apk
```

Windows 便携目录写入 `release/时间戳/Jinchuan-版本-win32-x64`，EXE 为 `Jinchuan-版本.exe`；`release/latest.json` 记录最近产物、版本及完整启动路径。必须分发整个目录。Android 打包入口核对真实版本后归档到 `apps/mobile/build/verified-apks/`，文件名为 `Jinchuan-版本-build构建号-架构-debug或release.apk`，同目录 `latest.json` 记录最近交付包。标准 Flutter 和 Gradle 原始输出路径保留，交付时使用归档后的版本化文件。
