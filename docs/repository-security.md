# 仓库写入与分支保护

2026-10-21 已在 `YouHanHan/momentnest` 的 `main` 分支配置并通过 GitHub API 回查确认：

| 规则 | 当前设置 |
|---|---|
| 更新 main | 必须通过 Pull Request |
| 管理员 | 同样执行分支保护 |
| 其他人的审批数 | 0，单人维护者可自行合并自己的 PR |
| 强制推送 | 禁止 |
| 删除 main | 禁止 |
| 未解决的 PR 讨论 | 阻止合并 |
| 必须通过的 CI 检查 | 当前未配置；避免等待尚不存在的检查 |

仓库公开意味着其他人能阅读、下载和 Fork，不能凭地址直接写入原仓库。当前检查时只有所有者有管理与写入权限，没有其他协作者、待接受邀请或部署密钥。未来新增协作者需重新核对其权限；拥有写权限的人可以提交自己的分支和合并满足规则的 PR。

日常修改使用独立分支，推送后创建 PR，再由有写入权限的人合并。不要为了临时推送关闭保护，也不要使用强推改写 main。新增维护者后，可以将审批数改为 1 并配置代码所有者；只有一个维护者时不要要求自己的 PR 必须由另一人批准。

这些设置保存在 GitHub，克隆仓库或修改本文件不会自动设置其他仓库。当前配置可在 [分支设置](https://github.com/YouHanHan/momentnest/settings/branches) 查看；GitHub API 的只读核验入口为 `GET /repos/YouHanHan/momentnest/branches/main/protection`。管理员仍可按需要调整设置，保护不会转移仓库所有权或授予任何新账号权限。

漏洞报告流程见 [安全说明](../SECURITY.md)。私密漏洞报告开关与分支保护分别管理，不因设置分支保护而自动开启。
