## 重新定位照片库

登记日期：2026-10-05。以下是拟实施方案与验收要求，复选框完成后才能更新功能状态；本次仅登记计划。

### 目标与现状

用户自行把 `D:/照片库` 搬到 `E:/家庭照片` 后，在拾光匣中选择新位置，验证文件完整性，继续使用原照片库的收藏、宝宝归属、人脸结果与手机保存回执。原目录可以已经不可访问，无需为恢复图库重新上传照片。

目前 [Receiver.addDirectory](../apps/desktop/src/service/receiver.ts) 按规范路径查找目录，新路径会生成新的库身份；[MediaCatalog](../apps/desktop/src/service/media-catalog.ts) 按完整 SHA-256 与大小复用媒体记录，但重新扫描不会把原库回执转给新库。[回执类型](../apps/desktop/src/service/types.ts) 已保存库身份与相对路径，适合在保留原库身份的前提下重新绑定根目录。[产品设计](product-design.md#传输与保存核对) 规定目标库回执与完整内容核对规则；重新定位仍须通过验证后保持原库身份。

### 首期范围

- 支持 Windows 上同一台电脑的整个照片库更换位置，包括换盘符、更换根文件夹名称和完整复制后的重新定位；内部子目录与文件名称保持不变。
- 用户自行搬运或复制文件，应用只读取媒体并更新本机记录，不移动、删除、覆盖或改写任何照片、视频与导出副本。
- 保留 `receiver_id`、`library_id`、当前库选择与库名称；保持回执标识、保存时间、批次日期和内容指纹不变。
- 保留收藏、人工日期、宝宝加入与排除、参考人脸、头像关联、人物命名及已完成的人脸分析，复用应用数据目录中的有效缓存。
- 缺失、损坏、无法读取、路径冲突或验证中断均保留原配置。首版不提供跳过差异并强制切换的入口。
- 新目录中的额外文件不影响已有清单验证，也不会凭空取得上传回执；用户随后明确重新扫描，沿用现有索引与识别规则。

首期不包含文件改名或子目录重排后的内容找回、部分迁移、跨电脑迁移、历史扫描目录重新定位、应用 `.momentnest` 数据目录迁移、自动寻找新路径和后台文件夹监听。只有整库流程验收通过后，才评估扩大范围。

### 用户流程

1. 在「管理照片库」中为已有库提供「重新定位」；当前库不可用的提示也提供入口。操作针对明确的库身份，不自动创建新库。
2. 先检查冲突任务，再由主进程打开系统文件夹选择器。用户取消选择时不产生配置变更。
3. 展示原路径、新路径与核验范围，启动只读核对。显示已核对文件数、总数、完整匹配数及差异明细，提供取消。
4. 核对完成后展示结果。全部必需项通过时启用「确认使用新位置」；否则展示缺失、内容变化或无法读取的具体相对路径与原因，允许补齐后重试。
5. 用户确认后复检计划有效性，保存一致备份，再原子更新库根目录与相关媒体位置。提交成功后刷新列表、预览与保存位置，提示手机重新「核对电脑」。
6. 手机沿用原电脑与库身份，通过现有接口核实新位置上的原文件；原成功回执仍有效的照片继续显示「已传入」，不新增上传任务。

空库没有媒体索引和回执时，明确显示「没有可核对的原文件」，经用户确认可重新定位，但不得展示虚构的验证数量或备份成功状态。

### 文件验证规则

核验清单覆盖该库当前有效媒体位置和全部保存回执的相对路径。同一位置及相同内容重复登记时合并读取；若同一路径要求两个不同内容指纹，则列为冲突。已被替代或明确失效的媒体索引位置保留为历史，不充当当前文件；保存回执对应文件缺失仍是阻断项，不因旧目录离线而静默忽略。

每个候选文件必须通过规范路径与授权范围校验，并核对完整 SHA-256 与大小。文件名、尺寸、修改时间、缩略图和相似图片不能证明原文件一致；仅修改时间变化而完整内容相同可以通过。核对期间文件发生变化时，该项失败并要求重新核对。

拒绝选择规范化后相同的根目录、与原根目录互相包含的目录，以及已登记为另一照片库的目标目录；不会合并两个已有库。继续拒绝路径穿越、符号链接或目录联接越界。新目录需要满足接收库的读写要求，不能仅凭可读就宣称已恢复接收能力。

计划绑定原库身份、旧根路径、核验清单版本与新目录身份。确认时复检路径、文件状态和冲突任务；清单变更、目录离线或计划失效后必须重新核对。成功迁移只证明本次验证结果，后续手机核对仍验证实际原文件，不能永久沿用此前检查结论。

### 任务互斥与恢复

- 准备前拒绝该库未完成的上传或导入，以及会读取或修改相关位置的扫描、人脸分析、重建和导出；无法证明范围无交集的全局任务也阻止重新定位。失败但可续传的上传属于未完成任务，不能只检查正在接收的请求。
- 核验至确认期间，服务端阻止该库创建或继续冲突任务，并暂缓自动人脸队列；保护必须覆盖 HTTPS 请求与工作线程调用，不能只禁用界面按钮。核验期间的手机备份查询不采用尚未确认的新路径。
- 旧批次的目标与日期保持冻结，不把续传切向新位置。用户通过现有入口完成或明确取消未完成任务；原目录已经搬走且仍有续传任务时，需先恢复原目录完成处理，首期不迁移临时分块。
- 提交时将受影响的旧导入预览标记为需要重新生成，避免复用冻结的绝对路径。其他照片库与独立历史目录的配置保持原样；同一旧路径也登记为历史目录时，明确提示其仍需单独处理。
- 取消、校验失败或确认前退出，保留原根路径、回执与全部媒体记录。释放任务保护后恢复原有自动队列条件，手工暂停状态不改变。
- 在现有本机记录中保存计划状态、核对结果与重新定位历史，不新增数据库表或业务依赖。重启后未提交计划标为中断，重新验证与确认；已提交状态与根路径必须在同一事务保存，避免出现部分迁移。

### 实现安排

按下表顺序推进。服务规则和原子提交通过专项测试后，再接入桌面交互与手机联调；每一阶段完成时更新复选框和实际验证结果。

| 阶段 | 工作 | 涉及模块 | 完成条件 |
|---|---|---|---|
| 一 | 明确计划状态、核验清单、失败分类与任务保护 | shared 类型、Receiver、MediaCatalog | 清单及互斥规则有专项覆盖，不改变现有回执语义 |
| 二 | 实现异步核验、确认提交、取消与恢复 | service 工作线程、Store、files | 文件完整核验，失败保留原配置，提交具备原子性 |
| 三 | 接入受限桌面接口与重新定位弹窗 | main、preload、DesktopApi、App.vue | 系统授权选目录，来源与参数校验，进度和差异可查看 |
| 四 | 验证图库、备份状态与跨端兼容 | 桌面测试、Android 现有核对流程 | 原身份与回执保留，真实请求不触发重传，预览与缓存正确 |
| 五 | 完善文档并按既有入口交付 | 使用说明、产品设计、验收记录、打包脚本 | 验证记录区分自动测试、构建与设备验收，交付包版本递增 |

- [ ] 确定准备、核验、待确认、受阻、提交、完成、取消和中断的状态转换；确认和取消按计划标识幂等处理。
- [ ] 复用 `canonicalDirectory`、`safePath` 和 `hashFile`，在现有工作线程中以有界并发核验；长任务异步返回，界面可以读取进度与发起取消。
- [ ] 增加库级任务保护及清单版本检查，覆盖上传、导入、扫描、自动识别、手工识别与重建的冲突入口。
- [ ] 主进程选择新目录，预加载层仅开放准备、查看状态、确认与取消的专用方法；确认只提交计划标识，界面不能任意改路径或数据库。
- [ ] 提交前在应用数据目录生成并校验 SQLite 一致备份；事务中更新库根、该库当前媒体位置、失效导入计划及完成状态，记录原路径供追溯，不批量替换其他库、历史目录或独立导出记录的路径。
- [ ] 事务成功后同步或重新加载 `assets`、`locationAssets`、`locationHistory` 与浏览查询缓存。事务回滚时不得留下提前更新的内存数据；提交后刷新失败应重载已提交记录，不能继续提供旧路径。
- [ ] 复用完整内容身份和分析缓存，不运行整库人脸重建；迁移过程不创建、改写或转移上传成功回执。
- [ ] 在目录管理与离线提示接入入口，显示原路径、新路径、核验进度、差异及确认结果。清晰区分目录不可用、文件缺失与内容变化。
- [ ] Android 首先沿用现有接收端信息刷新与备份核对接口，不预设协议升级；联调检查库身份不变时能否刷新路径、预览详情和本机状态，发现实际兼容问题再做必要调整。
- [ ] 验收通过后更新使用说明、产品设计和验收记录，再按统一打包入口发布；当前计划登记不修改应用版本、不构建交付包。

### 验收条件

| 场景 | 必须满足的结果 |
|---|---|
| 完整搬家，原目录已不存在 | 新位置验证通过后保持原电脑与库身份；原图及视频可预览，重启后仍使用新位置 |
| 完整复制，旧目录仍存在 | 仅重新绑定所选库；两处原文件均保留，其他目录授权不自动改变 |
| 收藏、宝宝、头像、参考和人物记录 | 内容身份与业务字段保持，参考可用，已完成人脸分析不重复执行 |
| 手机重新核对与重复上传 | 原回执与保存时间不变，显示新位置；有效原文件继续为已传入，重复上传复用原回执 |
| 时间变化但字节相同 | 完整核验通过，位置状态更新，回执与人工记录保持 |
| 缺失、损坏、权限不足或目标离线 | 明确列出原因，禁止确认切换，不误判为迁移成功或新增备份 |
| 同名同大小但内容不同 | 哈希不符，拒绝通过，不借用旧回执 |
| 额外文件与既有失效历史 | 额外文件不获上传回执，失效历史不复活；缺失回执仍阻止切换 |
| 空库与错误目标 | 空库明确无媒体可核验；非空库选空目录受阻；重复库、同目录、父子目录和越界路径被拒绝 |
| 上传、导入、扫描及识别冲突 | 界面和服务均阻止，核验中新的冲突请求也被拒绝，批次日期与续传路径不变 |
| 取消、重复确认及计划失效 | 取消保留原配置；重复确认不重复改写，目录或清单变化必须重验 |
| 核验期间退出或重启 | 旧配置可恢复，未提交计划显示中断，不自动切换或沿用旧验证结果 |
| 提交失败与提交后退出 | 注入事务失败时数据库与内存一致保留原状态；已提交后退出则完整恢复新状态 |
| 大图库核验 | 进度反映真实清单，内存与并发有界，界面可交互和取消，不生成整库缩略图或重复识别 |
| 原媒体保护 | 全流程前后合成媒体哈希一致，不调用媒体删除、移动、覆盖或改写接口 |

先用隔离临时目录、合成照片与视频完成服务、事务、IPC 和界面专项测试，再运行必要的桌面回归、类型检查与生产构建。沿用 `npm run desktop:test`、`npm run build`、`npm run desktop:ui:test` 和 `npm run desktop:layout:test`；Android 有实际改动时运行相应分析与测试。最终以 Windows 便携包和 Android 真机验证目录迁移及备份核对，分别记录结果，不以结构检查代替真实设备验收。

### 后续候选

首期稳定后再评估文件改名或子目录重排后的按内容重新关联，以及历史扫描目录重新定位。两项保持独立范围，均不能凭匹配结果伪造当前库上传回执；当前不安排实现日期或版本。
